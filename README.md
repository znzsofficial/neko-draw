## 自画像参考图（1.4.0）

管理员在`[self_portrait]`设置`enabled=true`和`reference_path="/absolute/path/ref.jpg"`。路径必须是一张静态PNG/JPEG/WebP文件，不能是目录/符号链接，最大10MiB/4000万像素；仅管理员配置可指定，不接受模型传入本地路径。插件每次读取有界原字节、verify及实际解码，文件变化/缺失/损坏/超限明确失败，不偷偷退回纯文生图。图作为输入交给当前生图供应商（即使本机CPA也会转发上游），**不会单独把参考图发送QQ或放入模型聊天上下文/工具返回**；不要选含隐私的图片。

开启后，Planner条件提示引导自画像/自拍/以机器人为主角使用`neko_draw(prompt="场景、动作、服装或画风", use_self_reference=true)`，不必先query_memory重建外貌。插件确定性附图；模型是否每次正确选择该参数仍需自然使用观察，不以关键词硬猜“自己”是谁。未选择参数的普通文生图保持原行为；原聊天图片明确改图仍用neko_edit_image，不擅自替换成角色参考。参考关闭时保留旧记忆式自画像提示作为未配置安装的兼容路径。

参考图的外貌为视觉基础，不要求复制服装/构图；用户指定的新造型可作为本次变化。输出是否精确保持角色取决于模型，不能保证完全一致或冒充实拍。当前Gemini native会用inlineData，OpenAI会走images edits或chat图片输入，沿用既有供应商/超时/重试；Life签名无人环境插画直接走其原链路，永不自动附此人物图。普通`/draw`命令仍是原文生图命令，参考自画像入口由上述模型工具参数提供，不把命令文字当本地路径。

### 修改聊天图片时追加角色参考（1.4.1）

`neko_edit_image(prompt="修改要求及保留内容", source_message_id="当前聊天真实原图ID", use_self_reference=true)`会先读取聊天原图，再在最后追加1张管理员角色参考。前面的原图仍是编辑对象，最后图片仅核对机器人外貌，不把整幅构图换成参考图，也不默认把所有人物替换为该角色。改变人物身份必须来自本次用户要求；prompt写清哪些内容保留/改变，角色一致性仍取决于模型。

最多3张聊天原图＋1张参考（沿用原总4图限制）；4张聊天图时明确拒绝并提示用source_image_index选取，不静默丢图。找不到聊天原图时参考不能替代，参考失效/配置更改同样明确失败，不降级普通编辑。默认false不读取本地图，普通edit行为不变；取消传播、同聊天在途保护、图片大小/像素限制保留，不请求额外模型或第二次生成。

入口规则：新画机器人自己→draw＋true；修改指定原图→edit，只有涉及机器人外貌才＋true；用户自拍/其他人物/普通场景不设true；Life无人插画走Life工具。工具名不变，仅增加edit可选布尔参数并精简发现说明。

## 图生图

发图片或表情包后引用它发送 `/draw edit 把背景换成海边，保留人物外貌和动作`（也支持 `/draw 图生图 …`）。
自然聊天修改图片时，麦麦调用 `neko_edit_image`，用当前聊天中的真实 `source_message_id` 读取原图或引用图；也接受模型实际可见的短消息编号/工具媒体索引，不得编造编号。需要指定某张普通图片时填可选 `source_image_index`（0为第一张）；上下文回退默认只取第0张，普通完整消息ID未指定索引时保留原多图/引用逻辑。
找不到原图会提示补发，不会拿文字描述冒充图片，也不会自动选中无关的历史图片。

OpenAI 的 images 模式使用 multipart `/v1/images/edits`，chat 模式使用带 data URL 的多模态消息；
Gemini 原生模式使用 `inlineData`。auto 保留两条路线，但 HTTP 400 不切换端点。
最多 4 张 PNG/JPEG/WebP源图（表情包GIF/动图先转首帧PNG），每张10MiB；继续使用后台任务、状态查询和临时错误退避重试。宿主丢失原始文件或未提供二进制时仍须补发；不自行按描述、表情编号或任意URL猜图。

多图取回仍受宿主RPC整帧16MiB限制，单图10MiB/4张上限不代表任何组合都能通过传输；若超限且同聊天/消息ID缓存也不存在，会明确取图失败，需减少图片或重新发送，不擅自修改宿主上限。实际供应商改图与QQ最终发送仍需使用验收，读取成功不代表已生成成功。
图生图直接依据原图，不要求先查长期记忆。旧绘图插件不需要启用。

MaiBot 生图插件，只保留两条路：

- OpenAI 兼容接口。先请求 `/v1/images/generations`，失败再请求 `/v1/chat/completions`。很多中转的 `gpt-image` 只通其中一条。
- Gemini `generateContent`。需要图片模型，例如 `gemini-3.1-flash-image-preview`。

`general.provider` 失败后会试 `fallback_provider`。Gemini 官方地址在国内服务器上默认走 `http://127.0.0.1:7890`。

麦麦在用户要求画图时调用工具 `neko_draw`，问进度时调用 `neko_draw_status`。白名单里的人也可以发 `/draw 一只猫`，或者 `/draw 状态`。名单为空时这两条命令不生效。

画自己或自画像时，先用 `query_memory` 查长期记忆里的外貌，再写成一段完整的话。外貌不从人格设定里取，也不要编。画别人时按当前对话写。`masterpiece`、`1girl` 和一串逗号短词会被退回。

接口返回 HTTP 400 时不重试，也不改走另一个接口。下一轮规划收到接口说明：区分内容审核与模型、尺寸、源图参数错误，不把所有 400 都当成违规。

明确429限流或连接建立失败仍按`retry_times`退避；等待时间从`retry_delay_seconds`起翻倍。请求超时/连接中断/HTTP408或5xx不能确定上游是否已执行，记为unknown，不自动重试、换路由或切供应商；配置次数不变，不影响用户明确要求的新任务。发送异常/发送中取消也保留unknown，不宣称失败或自动补发。unknown终态只在15分钟内最多提示一次，可查状态；重载后内存记录不可恢复，Life持久admission仍禁止自动重放。OpenAI auto记住成功路径，同聊天在途保护保留。内部角色参考包装仅用于供应商输入，任务摘要/图片历史用用户原始画面要求。

复制 `config.example.toml` 为 `config.toml` 后填写密钥。不要把 `config.toml` 提交进仓库。

### Life群号/QQ号配置（1.3.1）

```toml
[life]
enabled = false       # 新安装默认关；原安装选择不自动变
group_ids = []        # 每项一个QQ群号字符串，如"123456789"，最多16项
user_ids = []         # 私聊QQ号，最多16项，不授权该用户所在群
account_id = ""      # 可选：机器人QQ号限制，不是聊天对象QQ号
sessions = []         # 高级兼容精确宿主会话ID
```

号码使用无空格/前导零/qq:前缀的ASCII纯数字。群私同号不混用；只查询宿主已有QQ会话列表（最多512条、2秒），以签名中的session精确匹配平台/聊天类型/目标/机器人账号，不猜session编码、不创建新聊天、不跨请求缓存。缺能力/查不到/超时/重复不明确会话均拒绝，未知仍不重放。

旧sessions与新号码**取并集**，空新字段不会撤销旧授权；迁移须删除同一目标的旧session，否则只删群号仍可能被旧ID放行。多机器人迁移应填原account_id，在已有元数据里核对授权集合未扩大；未确认的旧会话保留高级字段、不猜号码。Life侧号码与Draw侧号码仍需分别允许，不能只开一边就绕过另一边。

宿主lookup后及持久admission后重查配置/总开关，撤销名单或更改账号时未开始的任务拒绝。已交给供应商的工作不能承诺撤回；热重载按原生命周期取消/结算，不能删除life-admission.db来重试未知任务。测试仅假密钥/合成会话与Mock生成发送，不宣称真实QQ投递已验收。
